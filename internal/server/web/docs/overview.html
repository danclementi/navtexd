1. What navtexd is

navtexd receives NAVTEX maritime safety broadcasts from an audio or I/Q stream. It decodes them, identifies the transmitting station, tags and logs every message, and presents everything via a web interface. It is a single self-contained program and was inspired by the Windows program YaND ("Yet another NAVTEX Decoder", by the late Dirk Claessens). It aims to provide useful enhancements to YaND wherever appropriate while maintaining ease-of-use.

Not for navigation. NAVTEX reception here is experimental and error-prone. Never rely on this software for navigation, weather routing, collision avoidance or any other safety-of-life decision. Use certified equipment and official sources.

2. Client and server

  • Client-server design. The "navtexd" program itself does all the decoding and keeps the log. It runs in a terminal window. It does not have a user interface of its own, but instead includes a server that you access from a web browser for viewing and control purposes. The browser can be on the same computer that navtexd is running, or from anywhere that can reach that computer.
  • Multiple clients simultaneously. The purpose of supporting multiple clients is to allow an instance of navtex to be viewed by others who may find the information useful; perhaps for log review, perhaps to examine real-time propagationconditions.
  • Two roles are provided. Administrators (direct connections from the local machine or a private network) have full access (i.e. including change of all program options, editing and deletion of log entries, database management, and so on). Viewers (anyone arriving through a proxy or tunnel, such as a Cloudflare tunnel) are limited but can still view real-time decoding and live channel spectra, select andread log entries, and even generate reports.
  • Light on the network. Remote viewers get a lively feed with very low WAN data usage because pages and data are losslessly compressed.
  • These Help files themselves are served by the program and are viewable by everyone, viewers included.

3. Inputs

  • Up to FOUR channels at once. One program decodes, tags and logs messages from up to four channels simultaneously. Each channel can have its own frequency, input source, and decoder settings.
  • Real or complex audio. A channel accepts real-valued audio (a receiver's audio output, a sound card or virtual audio cable, a WAV file, raw samples on standard input) or complex I/Q from SDR hardware.
  • Several channels from one I/Q stream. Channels can share one input if desired. A single 48 kHz wideband I/Q stream can, for example, feed a 490 kHz and a 518 kHz decoder at the same time.
  • I/Q over the network. The program can accept I/Q streams over Ethernet from OpenHPSDR radios (Protocol 1: Hermes, Hermes Lite, ANAN and similar; Protocol 2: for example the HPSDR bridge of UberSDR, which needs it for more than one receiver), from an Airspy HF+ through the SpyServer program, and from an SDRplay receiver through the headless SDRconnect server.
  • NAVTEX channels. 518, 490, 486, 424 and 4209.5 kHz can be selected. Support for 424 kHz is incomplete at this time: a transmission on it may show no decoded text.
  • No calibration required. The carrier and the symbol timing are tracked continuously, so the sound card or SDR sample rate does not need to be calibrated.
  • Automatic polarity. The decoder detects and adapts, whether the audio signal is received in USB or LSB, selecting mark and space correctly.

4. Decoding

  • A streaming decoder: carrier search and tracking, symbol timing, SITOR-B framing, and combining of the two transmitted copies of every character.
  • Two framing methods can run side by side on different channels for comparison: hard (fast, needs a clean signal) and soft (locks later but works in more noise).
  • Unreadable characters are shown as ~. Optional spelling correction repairs them from a maritime vocabulary; the raw received text is always kept unchanged.
  • A message whose ZCZC was damaged is still recognised by its position and the identification group that follows.
  • Chinese text (486 kHz). China's national service sends each GB 2312 character as three letters. On a 486 kHz channel (and only there) the program reads those letters as Chinese characters. The Log and the Review show the characters; the letters that were received are kept, and are shown when the “show autocorrections” box is unticked. A letter lost or added in reception is bridged where the text allows, and a unit that cannot be read shows as □. Copy text in the Review gives the characters, which can be pasted into a translator.
  • Fragment dropping. Text received outside any message (mostly noise) is dropped unless it passes a vocabulary word test. The test and the vocabulary can be tuned, and you can add your own words.
  • Technical detail on how the decoder works, stage by stage, is in this section: How the demodulator works.

5. Monitoring

  • Thumbnail spectra are always visible at the top of every tab, so you can monitor activity while reviewing the log, generating reports, etc.
  • The Spectrum tab shows a large spectrum that can be zoomed and moved, with one trace for incoming spectrum and a second trace for the signal after the receiver's channel filter (which is what the demodulator actually sees).
  • Meters for input level, signal quality and CPU load, lock/sync/data indicators for each channel, and a ticker-tape display of the selected channel's live decode.
  • Scheduler (Options) sets the operator comment or a channel comment to a value at a time of day, every day, for example the antenna in use.
    • A time is a clock time in UTC or local time; local times may also be relative to sunrise, sunset or local midnight.
    • navtexd runs the schedule itself, so it works with no browser open, and after a restart every setting takes the value of its latest line.
    • The lines are kept in navtexd_schedule.json in the data folder.
  • Layouts: on a screen at least 1400 pixels wide, the Layout menu at the right of the tab bar shows several tabs side by side in tiles (for example Monitor and Schedule on the left, Spectrum and Log in the middle, Report and Options on the right). On a narrower window the page shows one tab at a time, as before. The layout is kept in this browser.
    • Tiles and stacks. A tile can hold one tab or a stack of tabs. Its tab strip at the top shows them: a click picks the one to show, the × takes a tab out of the tile, and the + button adds a tab. A tab is in one tile at a time, so it moves there from the tile that had it.
    • The ⋮ button of a tile adds a tile below, adds a column to the right, closes the tile or makes all sizes equal.
    • Moving tabs. Drag a tab title to move it within its tile (drop it at the place in the strip), or into another tile (drop it anywhere on that tile: it goes to the end of the strip, or where you drop it on the strip). It leaves the tile it came from. Escape cancels the drag.
    • The tab bar. A click on a tab in the tab bar goes to the tile that has it, or else joins the stack of the tile you used last.
    • Sizes. Drag the space between tiles to resize them; a double-click on it shares the space of its two neighbours equally.
    • Saving layouts. When you change a preset it becomes my layout, which stays in the Layout menu next to the presets; the presets themselves do not change. To keep a layout, choose Save this layout as… at the bottom of the Layout menu (or in the ⋮ menu of a tile) and give it a name; it then stays in the menu as it was saved, until you save it again under the same name. Delete a layout… removes one you saved or my layout, and takes a built-in layout out of the menu (Restore built-in layouts brings them back).
    • Keyboard shortcuts of the Log and the Report act on the tile you used last.
    • The top bar (dials, clock, small spectra, latest text) is the Instruments tab in tiled layouts: when a tile shows it, it leaves the top of the page; otherwise it stays at the top.
  • A System Log records what the program is doing, including a watchdog that reports an input that has stopped delivering samples.

6. The message log

  • Every message is stored with its time, channel, station, subject and serial number, in a log with filters (station, subject, text, distance) and de-duplication.
  • Multi-selection: Ctrl-click selects individual rows (i.e. log entries) and Shift-click selects a range. The selection can be reviewed, added to a report, or deleted.
  • Columns: drag a column title to move the column, drag the right edge of a title to resize it (double-click the edge: original width), and right-click a title (or choose Columns… in the row menu) to show or hide columns (the same menu has Original columns, which puts the standard set back). Besides the usual ones there are Bearing (degrees from your receiver, needs your position like the distance) and Score (the identification points). The choice is kept in this browser. The list is not sorted by column: its order is the time order set by the chrono / reverse buttons.
  • Station list (Stations tab): the list of the stations that navtexd knows, with the keywords used to recognise them.
    • Columns work as in the Log: drag to move, drag the edge to resize, right-click a title to choose (and Original columns to put the standard set back).
    • Sorting. Click a column title to sort by it (again: descending, a third time: unsorted; Shift-click adds a second sort key).
    • Filtering like a spreadsheet. The ▾ button of a title opens its filter: tick or untick values (each is shown with the number of stations that have it, and the list follows the other filters) and search the values. For number columns (Area, Freq, Km, Brg, GID, UID, Heard) and dates (Last heard) you can give a smallest and largest value; for Brg a first value larger than the second wraps through north (350 to 10 gives the stations from 350° round to 10°). For text columns there is a contains / begins with / equals test. Filters of several columns apply together, and with the frequency choice and the search box; clear filters removes them.
    • Extra columns. GID and UID show how many keywords the station has, so 0 finds the stations that still need some. Heard is how many messages of your log were identified as the station. Last heard and Country are hidden until chosen.
    • Copy and CSV. copy puts the rows shown, with the columns shown, on the clipboard as tab-separated text (it pastes into a spreadsheet); CSV saves them as a file.
    • Editing. Of a station that comes with the program you can change only the keywords, or delete it (it stays in the list, blue and struck through, and is not used; Restore original brings it back). You can also add stations of your own. Your changes are kept apart from the shipped table, so an upgrade brings its corrections without losing them. How this works is in How station identification works, section 1.2.
    • Export, Import and Restore original table. Export saves the table in YaND format. Import can merge a file into the table (new stations and keywords) or replace the table by the file. Restore original table gives the whole table back as the program ships it.
    • The choices of columns, sorting and filters are kept in this browser.
  • Quick actions: Alt-click on a row adds that record to the report. Right-click on a row (or the Menu key) opens a menu with everything that can be done with the record or the selection: review, add to report, copy, identify again, choose another station, undo, delete. Shift + right-click gives the browser's own menu. The line under the message text lists the stations on air when the message began; the station it was named for is in bold.
  • Undo: deletions and edits can be undone, repeatedly, one step at a time. The undo history is kept on disk, so it survives a restart of the program (undo information is retained for 30 days).
  • Trash: deleted messages stay in the database for 30 days. The Database dialog lists them, with a search box, and brings back any of them in any order, whichever deletion they were part of.
  • Backups: before the log database is compacted, a backup copy is made automatically (the three newest are kept). Backups are also made before an import is made that would add to or replace the current log.
  • Messages are stored in one SQLite database file (messages.db) in the data folder, which other programs can open (the messages view is the readable table); all times are UTC.

7. Station identification

  • The B1 letter and the frequency do not name a station by themselves, so every message is scored against a station table (in YaND format). For each candidate station, the score combines unique keywords (the station's own name or call sign), geographical keywords (places named in its warnings, weighted by how few stations share them), the time slot, the distance from your position, and how often you have received that station before.
  • A station is named only when the evidence is clear. Otherwise the record stays unidentified and the ranked candidates with their scores are kept, so you can decide.
  • Identify again: after keywords are added to the station table, the messages that have no station (UNID) can be given another try, all at once (Database dialog, Identify again; messages that already have a station, and messages you edited, are not touched). The right-click menu of the Log has Identify again for one record: it starts from scratch and forgets the station, B1 and NAVAREA you gave it.
  • Review selected: with several records selected, Review (the button, Enter, or the right-click menu) reads just those, one after another, in list order; the header says n of m (selection). The selection is fixed when the review starts, so the table can be used meanwhile. Deleting a record takes it out of the set and shows the next one in the direction you were stepping; at the end of the selection (or of the list) a page says so, and Undo puts the record back.
  • Review tab: the reader is also a tab. Where the Review tab is on screen (the “Log and Review” layouts put it beside the Log) it follows the record selected in the Log and the Review button and Enter use it instead of opening the pop-up; otherwise the pop-up is used. Clicking a row in the table ends reading a selection.
  • Review pane: in the reader pop-up you can assign a station ID to a record yourself, chosen from the stations scheduled at that time or any station which broadcasts on that frequency. Such an identification is marked as forced when the message text does not support it.
  • Copy text and Copy all (Review pop-up and Review tab): Copy text puts the text of the message on the clipboard without the date and time, with its line breaks; Shift-click joins the lines into one paragraph (without spaces in Chinese). Copy all puts the text with the time stamp of each line on the clipboard.

8. Reporting

  • Multiple log entries are easily selected and, with a single click, transferred for report generation. The complete report is shown in the Report text tab, where the text can be edited as needed. The text follows the report list until you edit it; while it is edited, a change to the list asks first (OK discards the edits). On a screen where that tab is not shown beside the list, the Edit button in the Report tab opens the same text in a pop-up.
  • The report lists the messages by frequency (518, 490, 486, 424, then 4209.5 kHz) and by time within each frequency; every frequency that has messages starts with the column headings. The table in the Report tab has the same order.
  • The comment of each record (the operator and channel comments from when it was received) goes at the end of its line in the report; unchecking include comments leaves them out. The choice is kept in this browser.
  • Once reviewed, the report can be copied to the clipboard or saved as a file.
  • Currently, only YaND format is supported for report generation.
