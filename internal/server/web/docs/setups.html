Typical channel setups

The settings that matter for the most common ways of feeding navtexd. Everything is set under the Options tab in the Channel sub-tabs. Option names {input.source} are the variable names shown there, along with the default values of this version in parentheses.

Before you start

  • Each channel has its own frequency selector {channel.frequency_hz} and its own source controls. The first control {input.shared_from} sets whether the channel will share the source of another channel or will have its own. The second control {input.source} selects the type of source (if it has its own).
  • The decoder needs an approximate point to look for the NAVTEX carrier. It gets this hint from the parameter {input.*.lo_below_hz}. This represents how far below the carrier the receiver's dial is (in the case of real audio), or how far below the carrier the center frequency of the I/Q stream (I/Q) is. The automatic search limit {receiver.search_range_hz} sets the maximum range of the search from the expected carrier frequency. Leave {input.*.autotune} on: the carrier is then found and followed automatically.
  • You need not choose USB or LSB: the polarity can be detected automatically ({decoder.polarity} = auto), and no sample-rate calibration is needed.
  • How to see that it works. When a signal is available in a channel, click on its spectrum "thumbnail" at the top of the display; this selects that channel for viewing. You may then open the Spectrum tab for a detailed view. The carrier marker sits between two peaks 170 Hz apart; the orange trace (the signal after the channel filter) follows the signal; and the LOCK, SYNC and DATA indicators of the channel come on.

1. Real-valued audio (a receiver's audio output)

A conventional receiver in USB mode, with its audio going to a sound card or a virtual audio cable. The signal appears as a pair of tones in the audio.

OptionTypical valueNotes
{channel.frequency_hz}518000The NAVTEX channel: 518000, 490000, 486000, 424000 or 4209500
{input.shared_from}own inputown input or select another channel's input
{input.source}deviceSound card or virtual audio cable
{input.device.name}part of the device nameEmpty = the system default input. The program's -list-devices command lists the names.
{input.device.channels}11 = real audio, 2 = I/Q
{input.device.sample_rate_hz}48000Sound-card rates of 8 to 48 kHz are possible; 48000 is typical
{input.device.lo_below_hz}1000The receiver's dial frequency is 1 kHz below the channel
{input.device.manual_carrier_hz}1000The carrier is expected 1 kHz above the receiver's dial frequency
  • Dial the receiver to the channel minus {input.device.lo_below_hz} in USB: 517.000 kHz for 518 kHz, 489.000 kHz for 490 kHz. The carrier then lies at 1000 Hz in the audio. Keep it between about 0.5 and 2.5 kHz, away from 0 Hz and the top of the band.
  • LSB: if the receiver is in LSB, the dial is above the channel: give {input.device.lo_below_hz} a negative value (−1000, dial 519.000 kHz). The two tones are then swapped, which the automatic polarity detection handles.
  • One channel per audio stream. A narrow audio channel cannot hold both 518 and 490 kHz. For two channels use two audio inputs (two receivers, or two virtual cables), each channel with its own {input.device.name}.
  • Receiver filter: a USB passband of about 3 kHz is plenty for a carrier at 1000 Hz.
  • A stereo I/Q signal from a sound card (for example an SDR program's I/Q output over a virtual cable) uses the same options with {input.device.channels} = 2 and a higher sample rate; if left and right are exchanged, use {input.device.mirror_iq}.

2. Two channels (518 and 490 kHz) from one I/Q stream

A wideband I/Q stream holds both NAVTEX frequencies. One program opens it once, and both channels decode from the same samples, each with its own down-converter, carrier and settings.

ChannelOptionValue
Channel 1{channel.frequency_hz}518000
Channel 1{input.shared_from}0 (own input: it opens the stream)
Channel 1{input.source}spyserver or sdrconnect (see sections 3 and 4)
Channel 2{channel.frequency_hz}490000
Channel 2{input.shared_from}1 (“same input as Channel 1”)
  • The stream's centre is set by Channel 1: channel 1's frequency minus its {input.*.lo_below_hz}. With the default of 1000 Hz and 518 kHz, the centre is 517 kHz and the 490 kHz carrier is 27 kHz below it.
  • The span of the stream must hold both carriers with a margin of several kHz at each side. The 250 kS/s of SDRconnect and the 228 kS/s of SpyServer (±125 and ±114 kHz) hold 518 and 490 kHz easily; 424 kHz would be at the very edge.
  • The owner (channel 1) must be on and have an input of its own; a sharing channel cannot itself be shared. Restarting the owner restarts the channels that share it.
  • Channel 2 has no input options of its own. Its other settings (framing, filter, receiver options) are independent, so the two channels can also decode the same frequency with different settings: give both the same {channel.frequency_hz} and compare them (see the Compare options).
  • OpenHPSDR radios work differently: there each channel gets a receiver of its own inside the radio (section 5), so you do not use {input.shared_from}.

3. Airspy through SpyServer

Airspy's SpyServer program owns the Airspy (HF+ Discovery, Airspy One, RTL-SDR) and streams I/Q over TCP. It can run on the same computer, or on another computer or a Raspberry Pi on your network.

OptionTypical valueNotes
{input.source}spyserver
{input.spyserver.address}host:portEmpty = 127.0.0.1:5555, SpyServer on this computer
{input.spyserver.gain}−1−1 leaves the server's setting. Otherwise a gain index from 0 up to the receiver's maximum.
{input.spyserver.lo_below_hz}1000The I/Q stream is centred 1 kHz below the channel. A few kHz moves the carrier away from the receiver's DC spur.
{input.spyserver.mirror_iq}falseSwitch on only if the spectrum is mirrored (see section 5)
{input.spyserver.autotune}true
  • The sample rate is not an option: the decimation stage nearest to 250 kS/s is used (the HF+ Discovery: 228 kS/s, ±114 kHz around the centre).
  • Start SpyServer first and check that it is streaming. The program tunes the receiver to the centre it needs; it only receives.
  • Adjust the gain until INP.LEVEL stays out of the red on the strongest signals.
  • To decode 518 and 490 kHz from the same stream, add the second channel as in section 2.

4. SDRplay through SDRconnect (headless)

SDRconnect (version 1.0.9 or later), with its window or headless, owns the SDRplay receiver. navtexd is a client of SDRconnect's WebSocket server and asks it for the I/Q stream. Enable the WebSocket server in SDRconnect (Preferences, WebSocket Server); by default it listens on port 5454.

OptionTypical valueNotes
{input.source}sdrconnect
{input.sdrconnect.address}host:portEmpty = 127.0.0.1:5454, SDRconnect on this computer
{input.sdrconnect.device}e.g. RSPduoPart of the receiver's name or its serial number. Empty = the receiver SDRconnect has selected.
{input.sdrconnect.antenna}e.g. Tuner 1 50 ohm, HiZ PortAs SDRconnect names it; a unique part is enough. Empty = leave as it is.
{input.sdrconnect.lna_state}−1−1 leaves the receiver's setting. Otherwise the gain-reduction step.
{input.sdrconnect.lo_below_hz}1000The receiver is tuned 1 kHz below the channel
{input.sdrconnect.mirror_iq}false
{input.sdrconnect.autotune}true
  • The sample rate is fixed at 250 kS/s (±125 kHz around the centre).
  • Only one program should control the receiver. If another client changes the sample rate, the stream stops with an explanation, and a changed centre frequency is logged as a warning because the carrier is no longer where the decoder looks.
  • Adjust {input.sdrconnect.lna_state} (or the gain in SDRconnect) until INP.LEVEL stays out of the red.
  • To decode 518 and 490 kHz from the same stream, add the second channel as in section 2.

5. Hermes and other OpenHPSDR radios

I/Q spectrum data straight from an OpenHPSDR (Protocol 1) radio over the network: Hermes, Hermes Lite, ANAN, Pavel Demin's Red Pitaya and QMtech images, and UberSDR (RX-888 MKII). Receive only modes are supported, of course.

We refer to these OpenHPSDR devices as "radios", and each radio can provide multiple virtual "receivers". Each receiver delivers a certain width of radio spectrum at its own center frequency.

General setup:

  • Single receiver, single channel
    • Set the channel's frequency from the selector: {channel.frequency_hz}.
    • Disable input sharing: {input.shared_from} = "own input".
    • Set the channel's source: {input.source} = hpsdr
    • Set the radio's IP address: {input.hpsdr.address} = e.g. 192.168.1.50.
    • Set the receiver's sample rate: {input.hpsdr.sample_rate_hz} = typically 48000.
    • Set the local oscillator of the receiver to be near, but not exactly at, the selected channel frequency, to keep the LO spur away from it. Example: for a 518 kHz channel, we might set the LO to be 515 kHz. The LO setting is done indirectly by entering the difference between the channel frequency and the LO frequency. Using our example, we would set: {input.hpsdr.lo_below_hz} = 3000.
    • Set the manual carrier frequency to the same value as entered in the LO setting: {input.hpsdr.manual_carrier_hz} = e.g. 3000.
  • Single receiver, multiple channels
    • Setup the first channel as described above (Single receiver, single channel); EXCEPT...
    • Set the receiver's local oscillator to be in-between the channel frequencies so that none of them is more than 22 kHz away (in the usual case of a 48 kHz sample rate). Example: Suppose we have set this first channel to 518 kHz; and we want a second at 490 kHz, and a third at 486 kHz. We might set the LO to 500 kHz. The LO setting is done indirectly by entering the difference between this first channel's frequency and the LO frequency. Using our example, we would set: {input.hpsdr.lo_below_hz} = 18000.
    • Set the manual carrier frequency to the same value as entered in the LO setting: {input.hpsdr.manual_carrier_hz} = e.g. 18000.
    • For each other channel using this receiver, set the channel's frequency: {channel.frequency_hz} = e.g. 490 kHz.
    • For each other channel using this receiver, set its input sharing:{input.shared_from} = "same input as Channel x"
    • That's it. Remaining setup decisions are automatically calculated.
  • Multiple receivers, multiple channels
    • Set up each channel as described in Single receiver, single channel.
    • Make sure all channels are set to the SAME radio IP address.
    • Make sure all channels are set to the SAME sample rate.
